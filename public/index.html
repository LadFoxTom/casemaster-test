How a Casemaster 2.0 app is built

Three files is enough for a working app. Drop them under app/, push to git, and Vercel deploys it.

1

Define a business object

One .cms file under app/bo/<area>/ declares the table, columns, and primary key.

2

Get CRUD for free

The runtime serves /maintenance/<area>/<bo> — list, create, edit, delete — without any UI code.

3

Add custom pages

Files under app/page/ become routes at /page/foo/f/<function>. Read the DB, render HTML.

What a BO looks like

app/bo/crm/contact.cms — declares the table that auto-generates /maintenance/crm/contact:

resource main
    <@bo
        label:      'Contact',
        table:      'crm_contact',
        primaryKey: 'id',
        attributes: <
            id:        <@bo/attribute label: 'ID',        column: 'id',        dataType: dataType.Long>,
            full_name: <@bo/attribute label: 'Full name', column: 'full_name', dataType: dataType.String, length: 120>,
            email:     <@bo/attribute label: 'Email',     column: 'email',     dataType: dataType.String, length: 200>
        >
    >
end-resource

What a page looks like

Reachable at /page/foo/f/home:

function home()
    set('n', 0)
    iterate sql.fetch('SELECT count(*)::int AS n FROM crm_contact')
        set('n', bo.attr([r], 'n'))
    end-iterate

    response.setContentType('text/html')
    response.write(concat('<h1>', formatString('{0}', [n]), ' contacts</h1>'))
end-function

Built-in routes for this app

/page/foo/f/setup
Creates the schema and seeds 3 contacts + 5 tasks. Idempotent.
/page/foo/f/home
Dashboard with counts and the latest 5 of each entity.
/maintenance/crm/contact
Auto-generated CRUD for contacts.
/maintenance/crm/task
Auto-generated CRUD for tasks (FK to contact).
/page/foo/f/ping
Plain-text DB connectivity probe — useful in CI.
/api?diag=1
Registry diagnostics (loaded fns, BO count, env-var presence).
